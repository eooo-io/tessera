# Tessera v0.0 decision gate report

**Date:** 2026-07-06
**Scope:** end-to-end CLI validation of M1–M5 (vault → ingest → embeddings →
lenses → disclosure → receipts). Issue #24.

> Historical evidence only. This report describes format-v1 plaintext receipt
> storage and its then-current unkeyed chain. Format 2 supersedes that storage
> with encrypted `.trc` containers and owner-keyed local authentication as
> documented in [`ADR-0001`](adr/0001-receipt-protection-v0.1.md). The original
> measurements below are preserved rather than rewritten as current evidence.

## What was run

The full loop was exercised from the terminal against a small, realistic
two-topic corpus (building-safety docs in a `Building` space; cooking/gardening
in a `Personal` space), using the real ONNX embedding model
(`all-MiniLM-L6-v2`):

```
init → space create → import --accept → index
     → lens create → query --lens → receipts verify
     → eval --golden
```

Corpus: 5 documents / 5 chunks. Golden set: 4 questions (3 building, 1 personal).

## Metrics vs targets

| Metric | Target | Measured | Status |
|---|---|---|---|
| Recall@10 (owner view) | > 0.70 | 1.000 | ✅ |
| Recall@5 | — | 1.000 | — |
| MRR | — | 1.000 | — |
| Policy degradation (lens vs owner) | < 10% | 0% | ✅ |
| Every lens query → verifiable receipt | required | 5/5, chain intact | ✅ |
| Summary-mode verbatim leakage | none | 0 bytes | ✅ |

Policy degradation was measured two ways: (a) all three in-scope building
questions still returned the correct document as the top hit under a
`Building`-only lens (0% recall loss vs owner view); (b) the automated eval
test `eval::tests::lens_filtering_preserves_recall_within_budget` asserts
< 10% degradation on a distractor-laden two-space corpus.

## Policy-enforcement findings

- **Space isolation holds.** A `Building`-scoped lens queried with a
  Personal-topic question ("rye sourdough fermentation") never disclosed the
  Personal document — it returned only in-scope building content. Corroborated
  by the proptest suite (`policy_enforcement::random_lens_never_violates_constraints`,
  64 random policies/corpora) and the adversarial perfect-match blocked-space
  test.
- **Quarantine holds under lenses.** Pending/archived content never surfaces
  under any lens (`quarantined_content_never_surfaces_under_lens`).
- **Disclosure modes behave.** Summary mode disclosed 0 verbatim bytes (keyword
  digest only); excerpt mode truncated on UTF-8 boundaries and recorded exact
  bytes disclosed; full mode is fail-closed to excerpt unless explicitly
  allowed.

## Receipt usefulness

At the time of this gate, every lens-bound query ran inside a recording
`Session`; each finalized to a plaintext `receipts/<id>.json` in the vault
bundle. The then-current `tessera receipts verify` walked an unkeyed BLAKE3
hash chain and passed; editing any finalized receipt broke verification. That
historical result did not prove authenticity. HTML export produced a
standalone, dependency-free receipt. The receipt records purpose, lens, agent,
per-query artifacts + disclosure mode + bytes disclosed, and summary stats —
enough to answer "what did this agent see, and under what policy."

## Observations / candidate refinements (non-blocking)

1. **No relevance floor.** A lens with no strongly-matching in-scope document
   still returns the closest in-scope chunk (e.g., the sourdough probe returned
   a low-relevance building excerpt). This is not a policy violation — nothing
   out-of-scope leaked — but a minimum-score threshold would avoid disclosing
   weakly-matching content. Candidate for M6 polish.
2. **Corpus is small/synthetic.** Perfect recall here is expected; the value is
   that the eval harness + golden-set mechanism is in place to re-run against a
   real, larger, noisier personal corpus. Real-corpus numbers should be
   captured before v0.1.
3. **Summarizer is keyword-extractive (v1).** Adequate and leak-safe, but a
   local abstractive summary would read better; the `generate` seam is ready
   for it.

## Decision

All three quantitative gate criteria pass (Recall@10 > 0.70, policy degradation
< 10%, every query produces a verifiable receipt), and the qualitative
enforcement/receipt checks hold.

**Recommendation: proceed to M6 (Guardian / MCP server).** The retrieval,
policy, disclosure, and receipt substrate is sound and exercised end-to-end.
The observations above are refinements, not blockers, and can be scheduled
alongside or after M6.

**Decision of record (2026-07-06): PROCEED to M6.** All three quantitative
criteria passed and the qualitative enforcement/receipt checks hold on the real
embedding model through the full CLI loop; the caveats (small synthetic corpus,
no relevance floor) are non-blocking refinements tracked for M6+. Owner
confirmed proceed.
